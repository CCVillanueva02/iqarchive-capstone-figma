1. The Four Frontend-Backend Interaction Patterns

IQArchive operates on a hybrid architecture combining reactive Livewire state, client-side Alpine AJAX, Volt single-file components, and standard full-page Blade renders.
Pattern A: Livewire 4 RPC
Accreditation, Instruments, Admin
Reactive server-side state. Components bind via wire:model, trigger actions via wire:click, POST to /_livewire/update, and morph the DOM diffs dynamically without reloading.
Pattern B: Alpine.js + Fetch AJAX
Documents Subsystem (iqa-documents.js)
Client-side data store (3,905 lines of JS). Handles heavy uploads and interactive matrices by issuing fetch() requests to session-cookie-guarded internal endpoints in routes/web.php.
Pattern C: Livewire Volt Single-File
Account Settings (⚡profile.blade.php)
Combines PHP component logic and Blade template into a single file prefixed with the UTF-8 ⚡ lightning emoji, registered via Route::livewire().
Pattern D: Full Page Blade
Welcome, Google SSO, Dev Login
Traditional server-side rendering returning complete HTML responses, handling Google OAuth callbacks and developer role-switching handshakes.

4. Architectural Rules & Gotchas

Essential engineering rules that developers and agents must adhere to when modifying IQArchive.
1. Desktop-Only Viewport Policy: IQArchive is built exclusively for desktop workstations ($\ge$ 1024px). Smaller viewports trigger the global guard <x-mobile-unsupported />, rendering a full-screen block. Do not build responsive mobile views.
2. Two Distinct Instrument Subsystems in MySQL:
• Subsystem 1: instruments, instrument_areas, instrument_parameters, instrument_criteria (Dynamic AACCUP Module 4 hierarchy).
• Subsystem 2: self_survey_areas, self_survey_parameters, self_survey_indicators, self_survey_ratings (Institutional self-survey subsystem).
Do not join or query Subsystem 2 when modifying academic program instruments.
3. Multi-Role Session Precedence: Users can hold multiple roles via the role_user pivot. The active role is stored in session('active_role'). Always check permissions with $user->hasRole('...') rather than comparing against the legacy $user->role attribute.
4. Cookie-Protected "API" Endpoints: Routes prefixed with api/ in routes/web.php are internal AJAX endpoints protected by web session cookies and CSRF tokens. They do not accept Bearer tokens.
